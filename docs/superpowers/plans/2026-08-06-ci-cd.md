# CI/CD Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a GitHub Actions workflow that runs lint, test, build, and format checks on every PR against `main` and every push to `main`; stop the pre-existing `static.yml` from auto-deploying on push.

**Architecture:** Single new workflow file `.github/workflows/ci.yml` with one job (`checks`) running four sequential steps via the root `package.json` scripts, which turbo fans out across the workspace. One trigger edit to the existing `.github/workflows/static.yml`.

**Tech Stack:** GitHub Actions (`actions/checkout@v4`, `actions/setup-node@v4`), corepack, pnpm 11.20.0 (pinned via root `package.json`'s `packageManager` field), Node 22.

## Global Constraints

- Workflow triggers: `pull_request` targeting `main`, and `push` to `main` — both, per approved spec.
- pnpm version comes from `corepack enable` reading the root `package.json` `packageManager` field — never hardcode a pnpm version in the workflow YAML.
- Node version: `22` (matches local dev environment; no `.nvmrc` exists in this repo, so this plan does not add one).
- Steps run in this exact order and must not use `continue-on-error`: `pnpm lint`, then `pnpm test`, then `pnpm build`, then `pnpm format:check`.
- pnpm store caching via `actions/setup-node`'s built-in `cache: pnpm` option — no separate cache action, no turbo remote/local cache.
- Do NOT add DB/pgTAP tests (`supabase/tests/database/rls.test.sql`) to this workflow — explicitly out of scope, deferred to a future task.
- Do NOT touch `static.yml`'s deploy logic (the `jobs.deploy` steps) — only its `on:` triggers.
- Do NOT add branch protection rules — that's a GitHub repo setting the user configures manually after this workflow has run green at least once.

### Task 1: Add CI workflow and disable static.yml's auto-deploy trigger

**Files:**
- Create: `.github/workflows/ci.yml`
- Modify: `.github/workflows/static.yml` (trigger section only)

**Interfaces:**
- Consumes: root `package.json` scripts `lint`, `test`, `build`, `format:check` (all already exist and are exercised locally — this task does not modify them).
- Produces: nothing consumed by later tasks — this is the final task in this plan.

- [ ] **Step 1: Create the CI workflow file**

Create `.github/workflows/ci.yml` with this exact content:

```yaml
name: CI

on:
  pull_request:
    branches: ["main"]
  push:
    branches: ["main"]

jobs:
  checks:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout
        uses: actions/checkout@v4

      - name: Enable corepack
        run: corepack enable

      - name: Setup Node
        uses: actions/setup-node@v4
        with:
          node-version: 22
          cache: pnpm

      - name: Install dependencies
        run: pnpm install --frozen-lockfile

      - name: Lint
        run: pnpm lint

      - name: Test
        run: pnpm test

      - name: Build
        run: pnpm build

      - name: Format check
        run: pnpm format:check
```

- [ ] **Step 2: Validate the YAML parses correctly**

Run:

```bash
python3 -c "import yaml; yaml.safe_load(open('.github/workflows/ci.yml'))" && echo "VALID YAML"
```

Expected: prints `VALID YAML` with no errors. (This checks syntax only, not GitHub Actions schema — full validation happens when the workflow actually runs on GitHub, which is out of scope for this task; the controller handles that separately after this plan completes.)

- [ ] **Step 3: Verify each workflow step's command actually succeeds locally**

Run each command from the workflow, in order, from the repo root, and confirm each one exits 0:

```bash
corepack enable
pnpm install --frozen-lockfile
pnpm lint
pnpm test
pnpm build
pnpm format:check
```

Expected: all six commands complete with exit code 0. If `pnpm format:check` fails on a file unrelated to this task's changes (e.g. a pre-existing untracked gap), do not fix it as part of this task — note it in your report instead.

- [ ] **Step 4: Edit static.yml's trigger**

Open `.github/workflows/static.yml`. Find this block:

```yaml
on:
  # Runs on pushes targeting the default branch
  push:
    branches: ["main"]

  # Allows you to run this workflow manually from the Actions tab
  workflow_dispatch:
```

Replace it with:

```yaml
on:
  # Manual trigger only — this workflow predates the monorepo restructure
  # (apps/*, packages/*) and its "upload entire repository" step is stale;
  # disabled from auto-deploying on push until/unless it's revisited.
  workflow_dispatch:
```

Do not change anything else in the file — the `permissions:`, `concurrency:`, and `jobs:` blocks stay exactly as they are.

- [ ] **Step 5: Validate static.yml's YAML still parses**

Run:

```bash
python3 -c "import yaml; yaml.safe_load(open('.github/workflows/static.yml'))" && echo "VALID YAML"
```

Expected: prints `VALID YAML` with no errors.

Runs on PRs against main and pushes to main. static.yml predates the
monorepo restructure and is switched to manual-trigger-only rather than
auto-deploying stale content on every push."
